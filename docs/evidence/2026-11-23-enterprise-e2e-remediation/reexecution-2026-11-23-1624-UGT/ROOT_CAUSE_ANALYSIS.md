# Root-cause analysis

| Reported or discovered issue | Confirmed cause in this snapshot | Remediation implemented | Evidence / residual limitation |
|---|---|---|---|
| `require is not defined in ES module scope` from migration tooling | `backend/package.json` declares `type: module`, while `backend/scripts/migrate.js` and `backend/scripts/createIndexes.js` used CommonJS-style entrypoint code; the migration runner was also not native ESM | Converted migration runner and both CLIs to ESM; historical migration files load through a dedicated compatibility loader; CLI errors preserve non-zero exit status | Syntax and isolated loader tests pass. Actual DB migration status/up/down remain blocked by absent dependencies/MongoDB. |
| Index creation appeared successful after internal errors / swallowed errors | Existing index helper caught errors and logged without reliably failing the command | Added validated `ensureIndex()` primitive; original MongoDB errors are retained as `cause`; command returns non-zero on error | Unit tests pass for valid definitions and propagated index conflict. Real collection/index checks not run. |
| `TypeError` reading `ts.ScriptKind.JS` / fragile syntax-parser API mapping | Syntax gate relied on enum availability and did not provide robust extension mapping/API validation | Added syntax parser helper with explicit `.js/.mjs/.cjs/.jsx/.ts/.tsx` mapping, stable ScriptKind values, parser API checks and explicit unsupported-extension errors | Repository syntax gate parses 2,613 files. Full invalid-file fixture coverage is unit-tested. |
| `moment` / `dotenv` module errors in historic logs | Current backend manifest/lock already contains `dotenv` direct and `moment` transitively; extracted tree has no `node_modules`, so package resolution cannot succeed before install | Did not add redundant dependency declarations; added actionable module-loading errors distinguishing missing packages from missing application source | Actual module availability remains blocked until supported runtime and install. `bcrypt` native binary was not loaded/tested. |
| Windows EPERM risk during `npm ci` | Installing while a backend/frontend process has loaded native dependencies can lock files on Windows; prior execution logs included a locked bcrypt binary | New safe installer checks listeners on 3000/5000/9090, prints PID/command line/classification and refuses installation rather than killing processes; all installs use `npm ci` sequentially | Installer is blocked by the under-version runtime in this environment; Windows process-detection path was not executable here. No process is killed automatically. |
| Makefile used inconsistent package install behavior | Backend/frontend install targets used `npm install` rather than the locked installation path | Makefile delegates root/backend/frontend installation to the guarded `npm ci` script; success is printed only after zero exit | Dry-run target expansion inspected. Actual install intentionally blocked before npm ci. |
| Production verifier could accept status without proving correct JSON health/readiness or misroute | Transport contract needed explicit origin, TLS, content-type and health/readiness payload checks | Added tested verifier for HTTPS-only remote origins, local loopback exception only, timeout, manual redirect, JSON content-type/payload, route and network error classification | Unit tests cover mock responses. Live endpoint is unconfigured; real transport remains blocked. |
| Migration batch claim code lacked an argument binding | `claimMigration()` referenced `batch` in validation/update without destructuring the value | Added `batch = undefined` to the validated claim argument contract and regression assertion | Focused suite passes 29/29. DB-backed lease/concurrency test not run. |
| Dependency audit orchestration could misclassify npm error JSON as a vulnerability report | npm audit JSON error responses can omit `metadata.vulnerabilities`; no-count JSON must not be treated as clean | Updated audit summarizer to require all six numeric vulnerability counts and classify missing metadata as blocked | Six package audit attempts are blocked by registry DNS/timeouts; current counts are unknown, not zero. |

The `moment` and `dotenv` findings were not treated as verified package-manifest defects in this repository snapshot. No unsafe major-version updates or lockfile regeneration were performed.
