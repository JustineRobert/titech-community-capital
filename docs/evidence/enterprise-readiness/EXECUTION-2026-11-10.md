1. **Payroll authorization and reporting:** payroll report and webhook-audit reads now use the canonical TITech permission policy after the existing authentication and tenant middleware. ## 4. Remediation completed

### 4.1 Payroll authorization and report truthfulness

Changed source files include:

- `backend/security/rbacPolicy.js`
- `backend/models/User.js`
- `backend/utils/admin/adminValidation.js`
- `backend/modules/payroll/payroll.routes.js`
- `backend/modules/payroll/payroll.constants.cjs`
- `backend/modules/payroll/payroll.service.cjs`
- `backend/modules/payroll/payroll.authorization.cjs` (new)
- `frontend/src/pages/Payroll.jsx`
- `frontend/src/__tests__/payroll/payrollPage.contract.test.jsx`
- `backend/tests/unit/payroll/payroll.read-authorization.test.mjs` (new)

**Source finding:** The payroll route's legacy role allowlist did not consistently recognize the canonical role names normalized by TITech's central RBAC/authentication policy. The tenant middleware was already mounted ahead of the payroll route permission check. That mismatch is a credible source-level cause for an inappropriate 403 to canonical-role users; an actual authenticated HTTP request was not reproduced because the application dependencies and database are unavailable.

**Applied change:** The `/report` and `/testWebhook/auditLogs` read endpoints now call the canonical permission policy for `payroll:report:read` and `payroll:webhook:audit:read`. `payroll_officer` and `payroll_auditor` are distinct canonical roles with tenant-scoped assignment controls and limited permissions. `tenant_admin` gets report/audit read but not general payroll mutation. The existing tenant middleware and tenant-scoped service queries remain in place. Process/reconcile/retry routes remain restricted to the administrative payroll role; the payroll officer does not receive those controls.

**Frontend change:** `Promise.allSettled` keeps report, subscription and audit results independent. Report state distinguishes loading, loaded, forbidden and error. When data retrieval fails, totals are displayed as unavailable rather than numeric zero and the batch list explains that it is not an empty result. Unauthorized roles are not sent requests for payroll report/audit resources they cannot read.

**Evidence:** Eight targeted Node.js authorization tests pass. The frontend Vitest contract tests were updated but not executed because `vitest` is not installed. No runtime HTTP test against MongoDB-backed payroll collections was possible. Therefore the historical 403 is source-level remediated but is **not yet closed as a runtime defect**.
