## Why zero-byte files are not blindly filled

The repository contains legacy, compatibility, governance, resilience, commercial and abandoned scaffolding. Replacing every empty file with speculative code would create unverified behavior and duplicate architecture.

Therefore the audit classifies empty files and keeps the canonical financial surface strict while leaving non-canonical debt visible for targeted remediation.

## Remediation policy

For every debt item:

```text
inspect -> classify -> preserve/repair -> test -> deprecate/remove -> document
```

Never:

```text
delete -> rewrite -> assume
```

## Current priority

### P0

Any issue touching payment initiation, callbacks, idempotency, ledger posting, balances, settlement, reconciliation, reversals or tenant isolation.

### P1

Runtime recovery, observability, backup/restore, security, CI release gates and provider sandbox verification.

### P2

Repository-wide missing imports, CommonJS/ESM legacy normalization, duplicate modules and unused/empty scaffolding.

## Gate behavior

`check:architecture-debt` reports repository debt without pretending it has been resolved.

`release:gate:strict` continues to block critical financial-surface failures and repository-wide runtime import debt; the non-critical remainder remains explicitly visible until remediated.
