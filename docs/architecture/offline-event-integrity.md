# Offline Event Integrity — Version 1 Boundary

**Organization:** TITech Capital LTD  
**Product:** TITech Community Capital

## Current algorithm

The browser's `createOfflineEvent` helper and backend `OfflineSyncService.validateEvent` use SHA-256 over UTF-8 JSON generated by a recursively key-sorting serializer. The current verifier removes `eventHash` and the following outbox-only delivery fields before recalculating the hash: `status`, `attempts`, `createdAt`, `updatedAt`, and `lastError`. These exclusions are narrow and explicit. Other fields remain part of the integrity envelope and are not silently ignored.

The currently tested envelope includes event identity and version/type fields, tenant/device references, event payload, event sequence/idempotency fields where produced by the browser, and any other immutable fields present in the original event. The concrete `createOfflineEvent` output and validator code remain the executable source of truth; update golden vectors whenever the envelope is intentionally versioned.

## Verified locally

The `offline-contract.test.mjs` golden-vector test verifies browser/server agreement, a nested property-order variation, a non-ASCII string, mutation of the listed delivery metadata, payload tampering, an unsupported event version, and unknown-field tampering.

## Residual protocol gaps

This implementation has not established a formal RFC 8785/JCS or equivalent cross-language canonical JSON profile, numeric edge-case vectors across every supported runtime, Unicode normalization semantics, or a registered asymmetric device-key lifecycle. The existing symmetric device credential check does not prove a separately signed event or human consent. The service readiness gate explicitly requires a `verifyEventSignature` collaborator, which is absent in the supplied snapshot; therefore the sync endpoint must remain not-ready.

## Do not weaken

- Never skip or trust client-provided `eventHash` without server recomputation.
- Never strip arbitrary fields just to make a failing hash compare pass.
- Never interpret an event hash as proof that the sending person is authorized.
- Never authorize tenant context from an event payload or header.
- Never store reusable authentication secrets in the outbox.
- Never let valid event integrity override device revocation, RBAC, business policy, durable idempotency, the financial transaction boundary, or reconciliation.
