# Regulated vs Non-Regulated Activities Matrix

| Activity / capability | Intended TITech posture | Initial classification | Regulated-party dependency | Evidence required before production |
|---|---|---|---|---|
| SaaS member/group records | Provide software | Technology/data service | Institution | Contract + privacy controls |
| Financial ledger software | Provide software/control record | Technology/control | Institution/accounting owner | CoA policy + journal controls + audit |
| Payment initiation | Orchestrate | Boundary-sensitive | Licensed PSP/bank | Contract + legal interpretation + sandbox proof |
| Payment execution | Do not execute independently in core model | Regulated | PSP/bank | Provider authorization + transaction proof |
| Funds custody | No custody in core model | Avoid | Regulated institution | Written custody boundary |
| Electronic-money issuance | Not planned in core model | Regulated | Licensed issuer | Separate legal strategy |
| Settlement | Match/control | Boundary-sensitive | Bank/PSP | Settlement contract + evidence |
| Lending decision | Risk intelligence | Partner-controlled | Licensed lender | Decision RACI + model governance |
| KYC/AML | Workflow/evidence support | Shared | Responsible regulated institution | RACI + escalation + audit |
| Personal-data processing | Platform operation | Data-protection governed | Controller/processor relationship | DPIA / contract / notices / controls |
| Regulatory filing | Reporting support | Institution-owned | Institution | Approval workflow + filing evidence |
